## Finish line (one sentence)

The existing HERMES loop runs on **live** search data (not a hand-seeded baseline), discovers its own keywords, enriches opportunities with real search-volume/competition data, and — the video's signature move — **drafts content then asks the founder targeted questions to inject lived experience** before the approval-gated publish.

## Critical reframing `[VERIFIED]`

This is **not a build** — Synthex already implements ~90% of the video as the internal **HERMES** subsystem. The verification pass confirmed:

- Three crons **registered and scheduled in `vercel.json`** (`hermes-discover` 16:00 UTC, `hermes-draft` 17:00 UTC, `hermes-digest` Sun 22:00 UTC), each auth'd by `CRON_SECRET_HERMES_*` (`lib/auth/cron-auth.ts`).
- `HermesConfig` model (`prisma/schema.prisma:6694`) gates per-org: `enabled` (default **false**), `brandSlug`, `dailyQuota` (5), `voiceFloor` (70), `metadata.trafficBaseline`.
- Loop is real: discovery sweep → gap engine (Haiku-classified) → draft (`lib/hermes/generator/draft.ts`) → voice+readability gate (log-only in H-1, hard-fails block) → calendar write as `pending_approval` → weekly Telegram digest.
- **No org is currently `enabled`** → the pilot is dormant by design, not broken.

So the work splits into **(A) activate the pilot safely** and **(B) close the 8 genuine gaps** vs the video.

## Part A — Activate the H-1 pilot for one org

Condensed from the verified activation checklist. **Safe, reversible up to the go-live flip.**

1. **Pre-flight (safe):** ensure an active `BusinessOwnership` row for the org; confirm a valid `BrandConfig.slug`; create the `HermesConfig` row with `enabled:false`.
2. **Baseline seed (safe):** populate `HermesConfig.metadata.trafficBaseline` with ≥7 days `{date,value}` + a `trafficBaselineSource` note, and `currentTrafficValue`. _(Gap-closing Part B-1 removes this manual step.)_
3. **Env (gated — Vercel dashboard):** confirm `CRON_SECRET_HERMES_*`, escalation vars (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` or `HERMES_LINEAR_TEAM_ID`+`LINEAR_API_KEY`), and `HERMES_ESCALATION_DRY_RUN=true` while testing.
4. **Dry-run (safe):** `curl` each cron with its bearer secret; expect `processed:1, errors:0`; check Vercel logs + that the digest reaches Telegram/Linear.
5. **Go-live (IRREVERSIBLE — founder-gated):** flip `enabled:true`. Crons then run daily. `enabled:false` pauses instantly. Watch the first week's digest.

> **Gate:** steps 3 and 5 touch prod env/data → founder's typed approval per Synthex DB/secret rules. No autonomous activation.

## Part B — Gap-closing roadmap (prioritised by value × safety)

Each item: what the video does · what exists today `[VERIFIED]` · the gap · the approach (reuse-first) · gating.

### P0 — High value, safe, no external dependency

**B-5 · Draft-then-ask-questions (the video's signature move) — HER-7**

- _Video_ `[25:42]`: agent drafts ~60%, then asks the human topic questions to inject lived experience before finishing — "what makes content actually good."
- _Today_ `[VERIFIED]`: `generateDraft()` is a single Haiku call, no human turn (`lib/hermes/generator/draft.ts`). ABSENT.
- _Approach:_ split drafting into (a) draft + generate 2–3 targeted questions, (b) deliver questions over the **existing Telegram channel** (`sendEscalation`) tied to the candidate, (c) on reply, finalise the draft incorporating the answers, then run the existing voice gate → calendar. Persist the Q&A on `HermesProposal`. Reuses Telegram + draft + gate; adds a "awaiting_author_input" state.
- _Gating:_ none external. Additive Prisma column (nullable) → founder-gated migration only.

**B-3 · GSC keyword auto-discovery — HER-5**

- _Video:_ the loop surfaces opportunities from real search data.
- _Today_ `[VERIFIED]`: keywords are **GBP-seeded** (`lib/seo/keyword-seeder.ts`, service+suburb variants); GSC is used for rank snapshots only.
- _Approach:_ add `seedKeywordsFromGSC(orgId)` that pulls top GSC queries (impressions/clicks via the existing `getSearchAnalytics()` in `lib/seo/rank-tracker.ts`) and creates `KeywordTarget` rows (respecting the 20/org cap), complementing — not replacing — the GBP seeder. Feed these into the gap engine.
- _Gating:_ none new (GSC OAuth already wired). Reversible.

**B-8 · Tests for the loop — HER-9** (runs alongside every item above)

- _Today_ `[VERIFIED]`: only a handoff integration test; no unit tests for discover/draft/digest/sweep/gate/gap-engine.
- _Approach:_ TDD per `api-testing` (401→403→400→200; real Supabase, no DB mocks). Cover: traffic-drop detection, gap dedup/priority, voice-gate decisions, and each new B-item. No new deps.

### P1 — High value, needs external credentials (gated)

**B-2 · GA4 Data API client — HER-4**

- _Today_ `[VERIFIED]`: `googleanalytics` OAuth is registered but **no code calls `analyticsdata.googleapis.com`**; GA4 is used only for client-side event firing.
- _Approach:_ add a GA4 Data API reader using the **already-installed `googleapis` (v171)** — no new dependency (`dependency-discipline` satisfied). Expose sessions/users/conversions per property.
- _Gating:_ GA4 property access via the existing OAuth consent — founder provisions property access.

**B-1 · Live traffic signal (retire the hand-seeded baseline) — HER-3**

- _Today_ `[VERIFIED]`: `sweep.ts` reads a hand-seeded `metadata.trafficBaseline`; comment marks "HER-2 will pull live."
- _Approach:_ replace the manual seed by computing the baseline + current value from **GA4 sessions (B-2)** and/or **GSC clicks** (`getSearchAnalytics`). Keep the same >30% drop logic; just change the data source. Removes Part A step 2 entirely.
- _Gating:_ depends on B-2 (GA4) being wired; otherwise GSC-only fallback (safe, already available).

**B-4 · DataForSEO enrichment — HER-6**

- _Video_ `[22:43]`: DataForSEO for keyword search volume/difficulty/competitor SERPs (cheaper than Ahrefs).
- _Today_ `[VERIFIED]`: `dataforseo` is a **registered credential type but unwired**; no third-party keyword/SERP API in the codebase. GSC gives only keywords you already rank for — no discovery or competitive landscape.
- _Approach:_ add a thin DataForSEO HTTP client (plain `fetch`, **no new dependency**) for search-volume + difficulty, used to (a) prioritise gap candidates and (b) enrich keyword discovery (B-3) with off-site keywords you don't yet rank for. Credentials via the existing platform-credentials vault pattern.
- _Gating:_ requires a **DataForSEO account + API login/password** (founder provisions; the $1 free credit covers a dry run). Spend is metered → founder-gated.

### P2 — Lower value / dependent

**B-6 · Competitor + regulatory discovery signals — HER-8**

- _Today_ `[VERIFIED]`: both `checkCompetitorSignal` and `checkRegulatorySignal` are empty stubs (`return []`, `// TODO HER-2`). Only `traffic_drop` is live.
- _Approach:_ competitor signal via DataForSEO SERP overlap (depends on **B-4**); regulatory via a per-brand feed. Wire into the existing `Promise.allSettled` sweep so failures stay isolated.
- _Gating:_ depends on B-4; regulatory feed source TBD.

**B-7 · Approval notification + SLA reminder — (fold into HER-7)**

- _Today_ `[VERIFIED]`: approval is via the Calendar UI (`PATCH /api/scheduler/posts/[postId]` → status); no proactive "draft pending" ping, no >24h reminder.
- _Approach:_ on calendar write, send a Telegram "draft pending approval" with a deep link; add a small cron that re-pings drafts pending >24h. Reuses `notification-channels.ts`.
- _Gating:_ none new.

## Out of scope (YAGNI)

- The video's multi-site "SEO operating system" (per-client manager separation) — Synthex is already multi-tenant per `organizationId`; revisit only if multiple brands run HERMES concurrently and collide.
- Replacing the Calendar-UI approval with a bespoke approval app — the existing UI + new pending-notification (B-7) is sufficient.
- Switching the loop's model provider — it correctly routes through the shared `lib/ai/model-router.ts`.

## Honest risks carried from verification `[VERIFIED]`

- Voice gate is **log-only** in H-1 (only hard-fails block) — fine for pilot; H-2 flips to enforcing. Don't assume drafts are voice-blocked yet.
- Model router assumes OpenAI/Anthropic keys exist — missing keys make draft generation fail and escalate to Linear (no graceful fallback). Confirm keys before go-live.
- Voice-gate foundation files are bundled at **build time** — editing `.claude/memory/ceo-foundation.md` requires a redeploy to take effect.

## Suggested sequencing

1. **Part A activation** (founder-gated) → get the pilot running on one org with the hand-seeded baseline.
2. **B-5 + B-3 + B-8** (P0, safe, no external deps) → the biggest content-quality lift + real keyword discovery + test coverage.
3. **B-2 → B-1** (GA4 → live traffic) → retire the manual baseline.
4. **B-4** (DataForSEO, once account provisioned) → competitive keyword data, unlocks **B-6**.
5. **B-7** polish.
