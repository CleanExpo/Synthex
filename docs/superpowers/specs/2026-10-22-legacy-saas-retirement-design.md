# Legacy SaaS surface retirement: design spec

**Status:** proposal (22/10/2026), not approved for build
**Client metric:** none: internal plumbing — the retirement moves no client number by itself, but it must not break the two things that do: the RestoreAssist trial page at `/restoreassist/pricing` (which sends visitors to the RestoreAssist trial) and the publish gate that still reads the `Subscription` table before any CARSI or RestoreAssist post goes out.
**Rests on:** synthex-intel-01-synthex-as-built (§4 "Wrong framing"), synthex-intel-07-advantages-and-proposals (proposal 5), and repo evidence at origin/main f12eb4294 plus the local-only branch `fix/front-door` (head 1c04696fd) in the canonical clone.
**Relation to the fleet programme:** no phase covers it. FD-8 retired P10 billing ("no Stripe, payments or subscription work") [VERIFIED DECISIONS.md:18], but no phase P-1..P9 removes what P10's predecessors left running, and M14 (white-label portal) is already "Cut" [VERIFIED docs/superpowers/specs/2026-10-17-vibe-to-leader-design.md:326]. This spec is cleanup that sits beside the programme; it must not touch the outcome plumbing that O7 relies on (`PipelineCostLedger`, cost metering).

## Finish line

On production, the public site has no self-serve path into Synthex: `/signup` refuses account creation without a valid invite, whatever the environment says. No public page links to `/signup` or a price list. `/waitlist` and the SaaS billing, invoice and referral screens redirect to a working page. Every Stripe, billing, referral and dunning API answers `410 Gone` and then is removed. Stripe no longer has a webhook endpoint pointed at Synthex. The seven SaaS crons (health-score, welcome-sequence, drip-day3/7/14, weekly-digest, unite-group-revenue) are gone from `vercel.json` and from disk. The Unite-Group connector no longer has `user.signup`, `user.upgrade`, `user.churn` or `payment.received` event types. Cost metering, spend ceilings, the `content.outcomes`/`campaign.*` connector events, the RestoreAssist trial page and the publish pipeline still work, and the checks in the verification plan show this. Each stage has its own reviewed PR. Stages that touch `vercel.json` or `prisma/migrations/**` carry the founder's `human-required` label.

## Decision up front

Build it, in-house, as removal. There is nothing to buy and no service to call. Retire in four stages, smallest risk first. (1) Land and finish `fix/front-door`, and make invite-only the code default instead of an opt-in flag. (2) Neutralise without deleting. API routes return `410`, pages redirect and the eight cron handlers return early. None of this touches a protected path. (3) Remove the seven SaaS crons from `vercel.json` together with their route files (`human-required`), then delete the dead code and the legacy connector event types. (4) Leave the `Subscription` table and the plan-entitlement code alone. They are now the live access and publish gate, so replacing them is a separate, later spec. Two items in the brief's list are **not** wrong framing, and this spec keeps them: `/restoreassist/pricing` (a RestoreAssist client marketing page) and `churn-scorer` (agency client-retention task AT-023). Disposition test: none of this moves O1-O7, which argues for doing it cheaply rather than cutting it. Stage 2 also closes a security gap (J11 Stripe webhook replay) and removes the main way an outsider can create a Synthex account, which is worth more than its cost.

## Goals & non-goals

**Goals**

- Close self-serve account creation fail-closed, so an unset environment variable cannot reopen it.
- Remove every public call to action that frames Synthex as a product someone buys.
- Stop the SaaS crons that email "new users" and push MRR to Unite-Group.
- Remove the Stripe write paths and the Stripe-to-connector event emitters.
- Remove the dead code and archive the docs that tell agents Synthex sells subscriptions (stage 4 docs sweep).
- Keep cost metering, spend quotas and per-organisation attribution exactly as they are (CLAUDE.md scope rule [VERIFIED CLAUDE.md:5-7]).

**Non-goals**

- Replacing the `Subscription` table as the entitlement, rate-limit and publish gate (separate spec, see Approach stage 5).
- Dropping any database table or row in this spec (`prisma/migrations/**` is protected, and dropping data is irreversible).
- Removing `/restoreassist/pricing` or any page that markets a Unite Group business.
- Removing `churn-scorer` before the founder rules on it (open question Q2).
- Rewriting `.planning/` history. It is archived and marked superseded, not edited line by line.
- Any Stripe account change other than disabling the Synthex webhook endpoint, and that one is a founder act.

### What `fix/front-door` covers and what remains

The branch is 7 commits on top of origin/main (`git -C <clone> log origin/main..fix/front-door`), 31 files, +1,245/−279. What it covers:

- The server again enforces invite-only (`40af57782`, `32fb64af0`), and invite consumption is atomic with account creation (`cd31117e3`).
- Public CTAs go to the CRM handoff and Opportunity Map (`99341f298`, `a5248c39c`), covering 13 public files: agencies, api-reference, benchmark, case-studies, compare/hootsuite, contact, features (three pages), integrations, roadmap, not-found, support, CaptionDemo, IntentScapeProductTour, nav-bar and MarketingLayout.
- `/pricing` is rewritten and its footer link removed.
- A guard test (`__tests__/landing/public-cta-funnel.test.ts`) fails if any public route file links `/signup` or `/pricing`.
- Approval steps go to named operators (`dc1883970`). This is unrelated to retirement.

**What remains:**

1. **The gate only works if an env flag is set.** On the branch, the server check is `if (isInviteOnlyMode() && !inviteCode)`. `isInviteOnlyMode()` returns `process.env.NEXT_PUBLIC_INVITE_ONLY_MODE === 'true'`, and its own header says "The gate is OFF unless … the literal string 'true'. Unset or any other value leaves signup open" [VERIFIED lib/auth/invite-mode.ts:4-12, identical on main and the branch]. Whether production sets the flag is **[UNVERIFIED]**. Stage 1 inverts this: invite-only always, with no flag to reopen it.
2. **`/signup` is still linked from these files on the branch:** `app/page-enhanced.tsx` (3), `components/landing/{CtaSection,cta-section,HeroSection,DemoConversionCard,UrlHealthCheck(2),clean-light-nav,dark-linear-nav,pricing-section(3)}.tsx` (`git grep` on `fix/front-door`). The funnel test only scans files reachable from public routes, so these files are probably not rendered by any public route [INFERENCE: the test was read, not run in this pass]. If so they are dead components. Stage 2 deletes the unreferenced ones, so a future import cannot bring the links back.
3. `lib/seo/metadata.ts:284` and `lib/google/indexing.ts:205` still list `/signup` as an SEO or indexing path. Remove them so Google is not asked to index a closed form. `robots.ts` already disallows it.
4. Nothing on the branch touches the dashboard billing screens, `SEOFeatureGate`, Stripe, crons, the connector or docs.
5. The branch exists only locally. It needs a rebase on current main, the release gate and a reviewed PR. The claims tripwire seeds were already regenerated once (`1c04696fd`).

### Stages (thinnest slice first)

**Stage 0: read-only evidence (no code).** This turns the UNVERIFIED runtime cells into facts before anything is switched off. An operator with the right access reads, without changing anything:

- Stripe dashboard: is a webhook endpoint pointed at `synthex.social`, and how many deliveries in the last 30 days?
- Vercel: cron invocation logs for the eight crons in the last 7 days.
- Database: count of `Subscription` rows by status and plan, and whether every org that publishes for CARSI and RestoreAssist has an `active` or `trialing` row. This protects publish gate 1.
- Env: the `NEXT_PUBLIC_INVITE_ONLY_MODE` value in production.
- Resend: emails sent by the drip and welcome crons in the last 30 days.

Output: a dated evidence note under `docs/pm/`. Stages 2 and 3 do not start until this exists.

**Stage 1: front door (no protected paths).** Rebase `fix/front-door`. Then:

- Change `isInviteOnlyMode()` to return `true` unless an explicit, documented, server-only `SYNTHEX_OPEN_SIGNUP=true` is set for local development. The default fails closed.
- Remove the remaining `/signup` references (remainders 2 and 3).
- Keep the funnel guard test.
- Add a server test: with the env var unset, `POST /api/auth/signup` without an invite returns 403.

**Stage 2: neutralise, do not delete (no protected paths).**

- Add one helper, `lib/http/retired.ts`, returning `410 Gone` with a JSON body `{ retired: true, reason: 'FD-8', since: '<date>' }` and a structured log line. Wire it into rows 4 (API), 7, 9, 10-GET, 11 and the 12 webhook.
- Webhook ordering (row 8): the founder disables the Stripe endpoint first. Stripe retries failed deliveries for up to three days and emails the account owner [UNVERIFIED: Stripe docs not fetched in this run]. Only then does the route return 410.
- Pages: `/waitlist` 308 to `/opportunity-map`; billing, invoices and referrals pages redirect to `/dashboard`. Use `config/legacy-path-redirects.mjs`, which `next.config.mjs` already imports, so no new mechanism is needed.
- Command palette and sidebar entries go. `SEOFeatureGate` drops the billing link.
- Crons: each of the seven handlers keeps `verifyCronRequest` and then returns `200 { skipped: 'retired-FD-8' }` before any database or email work. The handler stays a 2xx so Vercel does not report seven failing crons every day. The route file must stay, because `tests/auth/cron-route-coverage.test.ts` fails if a `vercel.json` cron has no route file using `verifyCronRequest` [VERIFIED tests/auth/cron-route-coverage.test.ts:4-6,34].

- Delete `lib/stripe/webhook-handlers.ts` and its route-safety baseline entry. `scripts/security/` is not protected.

- Delete `lib/retention/health-score-calculator.ts`, and `lib/admin/mrr-calculator.ts` if it has no other caller.

## Security & cost guardrails

- **Cost metering stays untouched.** This includes `lib/ai/budget-enforcer.ts`, which reads `OrgBudgetPolicy` and refuses spend if that read fails [VERIFIED lib/ai/budget-enforcer.ts:284-298]. It also covers `lib/ai/governor/*`, `lib/pipelines/track-cost.ts`, `lib/minimax/credit-guard.ts` and `PipelineCostLedger` (the O7 data). None of them read `Subscription` (grep of `prisma.subscription`/`subscriptionService`: 39 files, none under `lib/ai/governor`, `lib/budget` or `lib/pipelines`). A guard test in stage 2 asserts that these modules import nothing from `lib/stripe` or `lib/billing`.
- `app/api/billing/usage` is plan quota display, not cost metering. Retiring it removes no spend control.
- **Fail-closed sign-up:** stage 1 makes invite-only the default with no public env flag. The opt-out flag is server-only and never `NEXT_PUBLIC_*`.
- **The publish gate must not flip.** Stage 2 does not change `safetyChecks.ts`. Disabling the Stripe webhook freezes `Subscription` statuses, so no new cancellation can block CARSI or RestoreAssist publishing. Stage 0 checks that those orgs already pass gate 1.
- **Webhook security:** retiring the Stripe route removes the J11 replay surface for Stripe events. Internal events keep the J11 gap, which stays on the backlog. The public affiliate conversion webhook also goes to 410 (row 12).
- **Cost saved:** the weekly-digest OpenRouter calls and the Resend sends from four email crons stop. Amounts are [UNVERIFIED]; stage 0 measures them.
- **Credentials:** the founder disables the Stripe webhook endpoint. No secret is read or rotated by an agent. Removing `STRIPE_*` env vars from Vercel is a later founder act after stage 3, not part of this spec.
- **Protected paths:** `vercel.json` (stage 3) and `prisma/migrations/**` (stage 5) are in `scripts/fleet/policy.json` `protected_paths` (read 22/10/2026). They need a declared fleet commit or the founder's `human-required` label.
